h1. Redmine OmniAuth SAML plugin

This plugins adds SAML authentication support for "Redmine":http://www.redmine.org thanks to the "OmniAuth authentication framework":https://github.com/intridea/omniauth and specially thanks to "Redmine Omniauth CAS Plugin":https://github.com/jbbarth/redmine_omniauth_cas.

This repository is a fork of the "original plugin":https://github.com/chrodriguez/redmine_omniauth_saml by Christian A. Rodriguez, now archived. Many thanks to him and to all upstream contributors for the original work.

h2. Install

You can first take a look at general instructions for plugins "here":http://www.redmine.org/wiki/redmine/Plugins.

Note that this branch is *only compatible with Redmine 6.0 or higher*. Earlier Redmine versions have reached end of life and are not supported.

Then :
* clone this repository in your plugins/ directory ; if you have a doubt you put it at the good level, you can go to your redmine root directoryand check you have a @plugins/redmine_omniauth_saml/init.rb@ file
* install the dependencies with bundler : @bundle install@
* run this command from your redmine root directory; it applies the plugin's database migration and copies the assets : @RAILS_ENV=production bundle exec rake redmine:plugins@
* restart your Redmine instance (depends on how you host it)

Finally you *must* configure your SAML settings adding a file in @<redmine_folder>/config/initializers@ for example named @saml.rb@ (the name is not important, but it must be a ruby file). A sample file is given in the plugin root folder named @sample-saml-initializers.rb@

Finaly you need to configure some minor options for the plugin to work, in "Administration" > "Plugins" > "Configure" on the OmniAuth SAML plugin line.


h2. Known issues

* SP-initiated single logout (used when @signout_url@ is configured) sends a wrong NameID to the identity provider: the configured field name itself (e.g. @mail@) instead of the user's value for that field. Deployments leaving @signout_url@ empty are unaffected.

h2. Running the tests

The plugin ships an integration test suite which runs inside a Redmine host application. From your redmine root directory:

<pre>
RAILS_ENV=test bundle exec rake redmine:plugins:test NAME=redmine_omniauth_saml
</pre>

The GitHub Actions workflow in @.github/workflows/test.yml@ prepares such an application from scratch for each supported Redmine branch with MariaDB, and can also be executed locally with "act":https://github.com/nektos/act by running @act push@ from the plugin root. Note for act users: recent Docker releases reject the runner-image @/var/run@ symlink during action setup ("nektos/act#6092":https://github.com/nektos/act/issues/6092); until the Docker-side fix ships, use a runner image where @/var/run@ is a real directory.
